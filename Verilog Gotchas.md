# Verilog and SystemVerilog Gotchas: Source-Review ReferenceThis checklist condenses the 101 gotchas from Stuart Sutherland and Don Mills into review-oriented questions. Treat each item as a prompt for manual review, linting, simulation, and cross-tool checks.## 1. Declarations, names, literals, and ports (Gotchas 1–20)1. **Case sensitivity** — Verify every identifier’s capitalisation; differently cased names are different objects.2. **Implicit nets** — Use `default_nettype none` and declare every net so a typo cannot create a one-bit wire.3. **Default one-bit nets** — Confirm every internal connection has an explicit width; undeclared/intermediate nets otherwise default to one bit.4. **Compilation-unit scope** — Do not rely on `$unit` declarations being visible across files or tool invocation modes; use packages.5. **Local declarations** — Place declarations where the selected Verilog/SystemVerilog grammar permits them, preferably before statements in a block.6. **Escaped hierarchical names** — Remember that an escaped identifier ends at whitespace; preserve the required terminating space in paths.7. **Automatic variables** — Do not access automatic task/function/block variables hierarchically; pass or return values explicitly.8. **Unnamed blocks** — Name blocks whose local objects must be referenced; unnamed-block hierarchy is unstable or unavailable.9. **Imported package items** — Refer to imported declarations in the scope where they were imported, or qualify them with `pkg::`.10. **Imported enum literals** — Import or qualify both the enum type and its labels; importing the type alone may not expose labels as expected.11. **Multiple package imports** — Avoid wildcard-import collisions; explicitly qualify ambiguous names.12. **Unsized integer base** — Check the default decimal interpretation of bare literals; state the base when intent matters.13. **Literal signedness** — Audit mixed signed/unsigned expressions and cast deliberately before arithmetic or comparison.14. **Sized signed literals** — Do not assume a signed literal sign-extends while being formed; verify width and extension explicitly.15. **Assignment size mismatch** — Check truncation, zero extension, and sign extension whenever source and destination widths differ.16. **All-ones constants** — Prefer `'1` for context-sized all ones; avoid width-dependent unsized constants.17. **Array literals vs concatenations** — Distinguish assignment patterns (`'{...}`) from packed concatenations (`{...}`).18. **Port connection rules** — Check direction, data type, width, signedness, ordering, and named associations at every instance.19. **Back-driven ports** — Ensure output/inout connections cannot unexpectedly drive a parent variable or contend with another source.20. **Real-valued ports** — Treat `real` ports as tool-sensitive; use portable wrappers or integer/fixed-point encodings where required.## 2. RTL modelling (Gotchas 21–43)21. **Functions in combinational sensitivity** — A manual sensitivity list may omit signals read inside a function; use `always_comb` or `@*`.22. **Arrays in sensitivity lists** — Ensure changes to every relevant array element trigger reevaluation; prefer `always_comb`.23. **Vectors with edge controls** — `posedge`/`negedge` on a vector observes only its least-significant bit; apply edge controls to scalar signals.24. **Expressions in sensitivity lists** — An event on an expression may miss operand changes that leave the result unchanged; list source signals or use `always_comb`.25. **Grouped sequential statements** — Always use `begin...end` when an event control governs more than one statement.26. **Reset structure** — Match reset polarity, synchrony, and sensitivity-list edges; check that all intended state is reset consistently.27. **Asynchronous set/reset modelling** — Verify simulation code maps to the intended technology and does not create synthesis/simulation disagreement.28. **Blocking assignments in clocked logic** — Use nonblocking assignments for state so statement order cannot create races or unintended feed-through.29. **When blocking is needed in sequential code** — Use blocking only for carefully scoped temporary calculations; assign architectural state nonblocking.30. **Nonblocking assignments in combinational logic** — Use blocking assignments in combinational procedures to avoid delta-cycle stale values and false storage behaviour.31. **Combinational assignment order** — Compute dependencies before uses, or use continuous assignments/functions, so outputs do not use previous values.32. **`casex`/`casez` masking** — Avoid `casex` in synthesizable RTL and use explicit wildcard intent; X/Z masking can hide real faults.33. **Incomplete decisions** — Give combinational outputs defaults and cover every branch to prevent unintended latches.34. **Overlapping decisions** — Detect overlapping `if`/`case` choices; use priority/unique constructs only when the assumptions are true.35. **Misused `unique case`** — Do not use `unique` merely to suppress warnings; simulation may optimise assumptions differently from hardware behaviour.36. **Resetting 2-state models** — A reset cannot reveal unknown power-up state in 2-state types; use 4-state RTL where X detection matters.37. **Locked enum state machines** — Provide legal recovery/default behaviour and test illegal-state injection; enum encodings can still lock up.38. **4-state X optimism/pessimism** — Review how X values flow through conditions and operators; neither hidden nor exaggerated X propagation should mask intent.39. **2-state types hiding faults** — Do not use `bit` where X/Z detection is required; conversion to two state silently maps unknowns.40. **Out-of-bounds array reads/writes** — Validate every index and range; out-of-range access can return X, do nothing, or vary by construct/tool.41. **Out-of-range enum assignments** — Avoid casts that force illegal values into enums; validate raw encodings before conversion.42. **Shared variables in modules** — Ensure a variable has one intended writer; use `always_comb`, `always_ff`, and linting to expose multiple drivers.43. **Shared variables in interfaces/packages** — Protect shared state against concurrent access and avoid hidden writers across scopes.## 3. Operators and expressions (Gotchas 44–60)44. **Assignment inside an expression** — Flag `=` where `==` was intended; parenthesise deliberate assignments.45. **Bitwise vs logical operators** — Check `& | ~` versus `&& || !`; they differ in width, short-circuiting, and X handling.46. **Equality choice** — Use `==/!=` for logical comparison and `===/!==` only when X/Z must compare as data.47. **Wildcard equality** — Use wildcard comparisons only with a documented don’t-care side; otherwise unknowns may match unexpectedly.48. **Relational signedness** — Cast operands to a common signedness and width before `<`, `>`, `<=`, or `>=`.49. **Expression width** — Determine the self/context-determined width of every arithmetic expression; size operands before the operation, not only the result.50. **Unary reduction vs binary operators** — Confirm that a one-operand `&`, `|`, or `^` is intended as a reduction.51. **Logical negation of vectors** — `!vector` tests whether the whole vector is zero; it is not bitwise inversion.52. **Shift width and signed fill** — Check result width and whether right shift should be logical `>>` or arithmetic `>>>`.53. **Signed arithmetic shifts** — An arithmetic shift only sign-fills a signed left operand; cast before shifting.54. **Power/operator corner cases** — Check exponentiation, division, and modulus for signedness, zero divisors, negative operands, and overflow.55. **Increment/decrement side effects** — Avoid relying on pre/post increment evaluation order inside larger expressions.56. **Conditional operator X merging** — With an unknown condition, `?:` can merge branch bits; verify that this is the desired X behaviour.57. **Operator precedence** — Parenthesise mixed arithmetic, shift, relational, equality, bitwise, and logical expressions.58. **Concatenation sizing** — Every concatenation item must have a known size; avoid unsized expressions and accidental truncation.59. **Replication counts** — Ensure replication counts are constant, non-negative, and produce the intended total width.60. **Streaming/packing order** — Verify bit ordering when packing, unpacking, slicing, or streaming between aggregates.## 4. General programming and simulation (Gotchas 61–75)61. **Null statements after control constructs** — Flag a stray semicolon after `if`, `for`, `while`, `repeat`, `forever`, or an event control.62. **Dangling `else`** — Use explicit blocks so every `else` is visibly paired with the intended `if`.63. **Loop termination and bounds** — Check initial value, comparison, step, signedness, overflow, and off-by-one behaviour.64. **Loop-variable lifetime** — Declare loop variables in the narrowest scope and do not depend on their value after the loop.65. **Fork/join control** — Verify `join`, `join_any`, or `join_none`, and ensure spawned processes are eventually synchronised or terminated.66. **Shared loop variables in threads** — Give each forked iteration an automatic copy; otherwise all threads may see the final loop value.67. **Static task/function locals** — Declare routines or locals `automatic` when concurrent calls require independent storage.68. **Re-entrant calls** — Do not assume a static routine is safe for recursion or overlapping invocations.69. **Function side effects** — Keep functions deterministic and avoid hidden writes, timing, or dependence on mutable global state.70. **Task output timing** — Remember that `output` arguments copy back on return, whereas `ref` aliases immediately; select deliberately.71. **Argument direction/defaults** — Confirm input/output/inout/ref direction, type, lifetime, and omitted/default argument semantics.72. **Event scheduling races** — Separate DUT drive and observation with clocking blocks or defined regions; do not depend on active-region order.73. **Zero-delay loops** — Ensure every forever/repeat path advances time or waits for an event.74. **`wait` versus event control** — A `wait` is level-sensitive and may complete immediately; an event control waits for a transition.75. **Named event races** — Trigger and wait on events using a protocol that cannot lose a notification between processes.## 5. Object-oriented and multi-threaded code (Gotchas 76–83)76. **Concurrent object access** — Protect shared properties, queues, and mailboxes; a class handle does not make operations atomic.77. **Handle assignment vs object copy** — `a = b` copies a handle, not the object; use an explicit copy/clone policy when independence is required.78. **Null handles** — Construct objects before dereference and check handles returned by factories, casts, mailboxes, and lookups.79. **Shallow copy** — A memberwise copy still shares nested handles; implement deep copy where ownership requires it.80. **Constructor chaining** — Call `super.new` correctly and initialise inherited state before using derived-class behaviour.81. **Virtual dispatch** — Declare base methods virtual when polymorphic behaviour is required; otherwise calls may bind to the base implementation.82. **Down-casting** — Use `$cast` and check its result; never assume a base handle refers to the desired derived type.83. **Process cleanup** — Track spawned processes and use disciplined shutdown; `disable fork` can terminate more activity than intended.## 6. Randomisation, coverage, and assertions (Gotchas 84–94)84. **Random stability** — Do not assume adding a random variable or changing call order leaves previous random sequences unchanged.85. **Constraint conflicts** — Check solver failures and return values from `randomize()`; never consume stale values after failure.86. **Distribution constraints** — Review `dist` weights and ranges; weights do not necessarily imply the probability intuition used by the reviewer.87. **`randc` exhaustion/interactions** — Understand cyclic-random behaviour, domain size, and how constraints affect the cycle.88. **`pre_randomize`/`post_randomize` side effects** — Keep callbacks predictable and verify they do not invalidate solved constraints.89. **Coverage sampling** — Sample at a stable, intentional time and only when data is valid; avoid double or premature sampling.90. **Coverage bins and crosses** — Check automatic bins, ignored/illegal bins, wildcard matching, and cross-product explosion against the verification plan.91. **Vacuous assertion success** — A pass action can run when the antecedent never meaningfully matched; measure attempts/non-vacuous successes separately.92. **Concurrent assertions in procedural code** — Understand that each execution can create a new assertion attempt; avoid unintended overlapping threads.93. **`assert ... else` binding** — Use blocks/formatting so the `else` belongs to the intended immediate or concurrent assertion.94. **Assertions that cannot fail** — Review implication, disable conditions, sampling, and antecedent reachability; prove that failure is actually possible.## 7. Tool compatibility (Gotchas 95–101)95. **Default time units/precision** — Declare `timeunit/timeprecision` (or controlled `timescale`) consistently; never rely on simulator defaults or file order.96. **Package chaining** — Avoid order-dependent transitive package visibility; import or qualify each dependency explicitly and compile packages in a defined order.97. **Random generators across tools** — Seeds do not guarantee identical sequences between simulators; require reproducibility within a tool/configuration and log all settings.98. **Memory loading with `always_latch`/`always_ff`** — Some tools treat `$readmemb/$readmemh` as an additional writer; isolate initialisation or use a portable memory wrapper.99. **Non-standard extensions** — Compile in strict standards mode and remove vendor-only syntax, pragmas, system tasks, or semantics unless deliberately isolated.100. **Array literal syntax** — Use standard assignment-pattern syntax and test parser support across the qualified tool set.101. **Floating-point module ports** — Tool support for `real` ports varies; encapsulate, use interfaces/DPI where appropriate, or replace with a portable representation.## Fast review pass- Compile with warnings elevated and implicit nets disabled.- Run lint for widths, signedness, latches, multiple drivers, incomplete/overlapping decisions, and unreachable code.- Run reset and X-propagation tests with 4-state models.- Check clock/reset/event controls and blocking/nonblocking discipline.- Exercise illegal states, out-of-range indices, boundary widths, and simultaneous operations.- Run at least two qualified tools or strict-language modes where portability matters.- For testbenches, log seeds/settings and check randomize, coverage, and assertion results rather than assuming success.
